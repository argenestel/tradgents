# Task: Monad testnet profile (chain 10143)

Scope: `monad/api`, `monad/agent-kit`, `monad/contracts`, plus a new `monad/deploy` folder. No git commands. Never use or look for real keys: everything is tested on a local `anvil` (it is installed; start it with `--chain-id 10143`) and with fixtures. Do not read anything under `~/.tradgents-testnet`. Read `docs/PRODUCTION.md` first. Mainnet behaviour must not weaken: mainnet stays the default and every mainnet check (chain id 143, pinned addresses, bytecode checks, Pyth freshness, USDC 6 decimals) keeps working and tested.

Goal: the same API, worker, signer and registry run against Monad **testnet** (chain id 10143, RPC https://testnet-rpc.monad.xyz) with a test DEX, so the product can be demonstrated end to end without real money.

## 1. Network profiles
Add one profile object per network (`mainnet`, `testnet`) holding: chain id, default RPC, WMON, USDC (or test stable) address and decimals, Uniswap V2 router and factory, Pyth contract, feed ids, explorer base URL, display name. Select it with `MONAD_NETWORK=mainnet|testnet` (default mainnet) in the API/worker and the signer policy; startup verifies `eth_chainId` equals the profile and that every pinned address has bytecode. For testnet, the router/factory/stable are **deployed by us** (below) so those three addresses come from env (`TESTNET_V2_ROUTER`, `TESTNET_V2_FACTORY`, `TESTNET_USDC`) and are verified for bytecode at startup; WMON testnet is `0xFb8bf4c1CC7a94c73D209a149eA2AbEa852BC541` (https://github.com/monad-crypto/protocols/blob/main/testnet/CANONICAL.jsonc; verify it with a read of `decimals()` and `symbol()` on the real testnet RPC, read-only calls are fine). Pyth on testnet: verify the contract address and that `getPriceUnsafe` works for the MON and USDC feed ids with read-only calls against https://testnet-rpc.monad.xyz; if a feed is missing or stale on testnet, add a clearly marked `TESTNET_FIXED_PRICES` fallback (stable = 1.00, MON from an env value) that is only accepted when `MONAD_NETWORK=testnet`, marked `estimated` quality, and says so in `/v1/meta`.

## 2. Test DEX deployment (`monad/deploy`)
A TypeScript script (viem, run with tsx) that, given `DEPLOYER_KEY_FILE`, `MONAD_RPC_URL` and the profile: (a) deploys a mintable 6-decimal `USDC` test token (small Solidity contract in `monad/contracts/src/test-tokens/`, compiled with forge; open mint is fine because it is testnet only and must refuse to compile into the mainnet deploy), (b) deploys Uniswap V2 Factory and Router02 from the official npm artifacts (`@uniswap/v2-core`, `@uniswap/v2-periphery`; pin versions in `monad/deploy/package.json`; Router02 takes the WMON address), (c) wraps MON into WMON, mints test USDC, creates the WMON/USDC pair and adds liquidity (amounts via flags, defaults small), (d) writes the resulting addresses to `monad/deploy/out/testnet.json` (gitignored) and prints them. Idempotent where practical (skip steps whose addresses already exist in the out file). Test it end to end on a local anvil with `--chain-id 10143` (deploy a WETH9-like contract there and pass it as the WMON address). The registry deploy script must also accept chain 10143 when `MONAD_NETWORK=testnet`.

## 3. Everything else follows the profile
API and worker (chain, tokens, feeds, explorer-independent), signer and CLI (pinned router/factory/tokens, deadline, simulation, approvals, USD limits) must use the profile. The EIP-712 domain already uses the configured chain id and registry address; check that it does. Add tests that run the full signer swap flow and the API worker against the local anvil testnet profile where practical, and unit tests for profile selection and the mainnet guards. `AGENTS.md`, READMEs and `.env.example` files document `MONAD_NETWORK=testnet`.
